# GLB 캐릭터가 "오른쪽 보임"일 수 있는 이유

## 1. 좌표계 차이

- **Three.js / 카메라**: Y가 위, 카메라는 보통 **+Z** 쪽에 있어서 원점(0,0,0)을 **-Z 방향**으로 바라봄.
- **glTF/GLB**: Y 위 기준. 제작 툴(Blender 등)에서는 보통 "앞"을 **-Z**로 두고 만듦.
- **우리 화면**: 카메라가 +Z에 있으니까, 모델이 **-Z를 보면** = 카메라를 보면 = **정면**이 보임.

## 2. "오른쪽 보고 있다"는 말의 의미

- 모델의 **앞쪽이 화면 오른쪽(+X)** 을 향해 있다 = 우리는 캐릭터 **옆모습(왼쪽 얼굴)** 을 보는 상태.
- 즉, **GLB 안에서 캐릭터의 "앞" 방향이 +X** 로 들어가 있을 가능성이 큼.
- 이런 경우, **Y축 기준으로 -90°** 회전하면 +X → +Z가 되어, 카메라(정면)를 보게 되어야 함.

## 3. 그런데도 오른쪽을 보는 이유 후보

1. **GLB의 실제 "앞" 방향이 다름**  
   - 앞이 -X(왼쪽)이면, -90°는 -X → -Z가 되어 등이 보임.  
   - 앞이 +Y/-Y이면, Y 회전만으로는 정면이 안 나올 수 있음.

2. **회전 각도 방향이 반대**  
   - Three.js에서 Y 기준 **양의 각도** = 위에서 봤을 때 **반시계**.  
   - 툴/엔진마다 회전 방향이 달라지면, -90°가 오히려 "한 바퀴 반대"처럼 동작할 수 있음.  
   → 그럴 때는 **+90° `[0, Math.PI/2, 0]`** 를 시도해 보는 게 좋음.

3. **다른 회전이 겹쳐 있음**  
   - GLB 루트나 부모 오브젝트에 이미 회전이 있으면, 우리가 준 Y 회전과 합쳐져서  
     "우리 의도 = 오른쪽 90° 만 돌리기"가 아니게 보일 수 있음.

4. **캐시/빌드**  
   - 예전 JS 번들이 그대로면, 수정한 회전값이 화면에 안 반영된 것처럼 보일 수 있음.  
   → 하드 리프레시(Ctrl+Shift+R 또는 Cmd+Shift+R) 후 다시 확인하는 게 좋음.

## 4. 정면으로 만들 때 시도 순서

- **1)** `[0, -Math.PI/2, 0]` (Y -90°)  
- **2)** `[0, Math.PI/2, 0]` (Y +90°)  
- **3)** `[0, Math.PI, 0]` (Y 180°)  

지금 코드는 1번을 쓰고 있고, 계속 오른쪽만 보이면 **2번(+90°)** 로 바꿔 보는 것을 권장함.

## 5. GLB에서 "앞" 방향 확인하는 방법

- [glTF Viewer](https://gltf-viewer.donmccurdy.com/) 에 `character1 (1).glb` 등을 올려서  
  기본 자세에서 **파란색 축(보통 Z)** 이 어디를 가리키는지 보면,  
  우리 씬에서 어떤 Y 각도를 줘야 정면이 되는지 추정하기 쉬움.
